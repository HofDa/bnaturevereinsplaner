# Frontend review — 2026-11-17

Fixed startup failures when browser preference storage is blocked. Theme and language changes remain usable when storage is unavailable or full, with temporary preferences held in the current tab. Invalid saved theme values fall back to the system preference.

Shared fields now expose their invalid state to assistive technology, including select and textarea controls. DataForm moves focus to the first invalid control after validation; required textareas participate in browser validation. Settings only shows the organization link to users with organization read permission.

Visual inspection found member filters squeezed into four unreadable dropdowns on phones. These now use two columns on small screens and one column below 480px, keeping search full width.

Validation:

- Focused member, error-boundary, and frontend-resilience UI checks passed (14 distinct tests; the final five resilience cases were rerun after the storage-full fix).
- Six desktop/mobile Chromium checks passed: member create/edit/search/export, automated WCAG checks on core views in both themes, and startup/theme/language with browser storage deliberately blocked.
- After the mobile filter adjustment, both member flows passed again, including new page-overflow and filter-width assertions. The final mobile screenshot was visually reviewed.
- Type checking, lint, formatting and diff checks passed; browser runs built the production frontend.

Coverage is limited to the flows above. Chromium mobile emulation does not replace Safari or physical-device validation.
